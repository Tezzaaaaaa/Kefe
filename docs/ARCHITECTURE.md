# Architecture

KEFE is a browser-based music visualiser and lyric-video editor. The editor (`apps/web`) is a static app: classic scripts that expose `window.kefe*` APIs, plus small ES modules that enhance native controls. The settings and export-progress dialogs, visualiser gallery and workspace/section navigation use React/Radix shadcn/ui components, and editor sliders, checkboxes, switches and editor panel selects use compatibility bridges; most editor controls and layouts are still legacy implementations. It is built with Vite and published to GitHub Pages. A small Express API (`apps/api`) and shared workspace packages (`packages/`) provide a health endpoint and generated API tooling; accounts and billing are not implemented.

### How the editor fits together

- **Legacy layer.** `editor.source.html` loads the effect, lyric, UI and visualiser scripts in a fixed order. Scripts communicate through globals such as `window.kefeEffects`, `window.kefeStyle` and `window.kefeSettings`. `effects/core.js` and `effects/manifest.js` must load before the lyric renderers.
- **Progressive enhancement.** The modules in `beui-src/` bridge or enhance existing native controls (range slider, settings dialog, visualiser tabs, command palette, mobile sidebar). Editor sliders, checkboxes, switches, editor panel selects, workspace/section tabs, visualiser gallery, transport, volume, export, header, toolbar launcher, cluster and panel buttons, toolbar sliders, checkboxes, segmented choices and selects, lyric, effect and preview navigation buttons, alerts, lyric-style colour inputs and swatches, lyric textarea, timing card and inputs, lyric display radio groups, export progress and the settings dialog use shadcn/ui components; most other editor controls are not yet shadcn components. The native control stays the source of truth: the enhancement mirrors its value and forwards events, although the editor workspace now depends on the tabs module loading successfully.
- **Standalone lyric demo.** `apple-lyrics-standalone.source.html` is its editable template; the build and publisher generate the public `apple-lyrics-standalone.html`. Its renderer is independent of the editor.
- **Legal pages.** `legal-src/` holds the editable privacy and terms templates. Vite builds them to the public `legal/` URLs; publishing updates those generated HTML files along with the assets. The content remains readable without JavaScript.
- **Header navigation.** `ui/structure.js` renders one header bar (`.kefe-sidebar`): the KEFE brand, a single Editor entry and the Settings, day/night and search actions; the repository link lives inside Settings. The header never repeats the six editor sections; those are reached through the editor's own section panels, the mobile drawer/dock, or the command palette.
- **Panels.** `ui/structure.js` builds the six editor sections (Media, Lyrics, Effects, Background Effects, Visualiser, Export). `ui/desktop-panels.js` and the settings panel place them in the three-panel desktop layout (and stack them below 1280px). `ui/panels-compact.css` is the compact styling layer for the side panels.
- **Toolbar.** `ui/toolbar.js` is the floating editor toolbar. On desktop it docks in the preview bar; each button opens a panel (layer, lyric effect, font, colour, canvas, more actions) that drives the canonical editor controls.

### Rules

- Effects are registered in `effects/manifest.js` and loaded by a script tag in `editor.source.html`.
- The `?v=` query strings on script and style tags are cache-busters. Update them when you change the file so browsers and the service worker pick up the new version.
- Never edit generated `editor.html`, `apple-lyrics-standalone.html`, `legal/privacy.html`, `legal/terms.html` or `assets/` by hand; the publish workflow regenerates them from `editor.source.html` on every push to `main` that touches the web sources.

## Development

```bash
pnpm install
pnpm --filter @kefe/web dev        # Vite dev server
pnpm --filter @kefe/web build      # production build into apps/web/dist-beui
pnpm typecheck                     # TypeScript for libs and the API
pnpm --filter @workspace/api-server dev   # run the API
```

### Workflows

| Workflow | When | What it does |
| --- | --- | --- |
| `beui-build.yml` | Pull requests and pushes touching `apps/web` | Build, run the smoke scripts and browser checks, compare layout against `main` on PRs |
| `beui-publish.yml` | Push to `main` | Build, verify, run the browser smoke test, then commit the generated `editor.html` and `assets/` |
| `package-release.yml` | Manual | Build the production editor, package the deployable `dist-beui` output as ZIP and tar.gz, and create a draft prerelease |
| `ios-companion-build.yml` | Changes to `apps/ios` or the editor and lock-screen files it depends on | Build the iOS companion |
