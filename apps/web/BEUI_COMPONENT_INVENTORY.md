# KEFE / beUI component ownership inventory

**Audit snapshot:** `e9b180bcb98a8492efdf4885caf3c2a6f5bbb1dc` (`arena/14540e51-kefe`; same snapshot as `main`).  
**Purpose:** record every production-loaded React bridge and its native/runtime contract before replacing or removing any bridge/build infrastructure. This is a source-level inventory, not proof of rendered equivalence.

## Architecture observed

- `index.html` redirects to `apps/web/editor.html`, which serves the built `dist-beui/editor.html`. The Vite build takes `editor.source.html`, bundles the imported React/Tailwind bridges into one JavaScript bundle and one stylesheet, then `scripts/copy-static.mjs` copies the native runtime/assets.
- The editor remains predominantly KEFE-authored markup and imperative JavaScript. `app/ui/structure.js` and `app/editor.js` generate the shell/panels; runtime files consume the existing DOM and event contracts. React components mount over, wrap, or mirror those DOM elements rather than owning the whole application.
- `editor.source.html` directly loads 15 `legacy-*-bridge.jsx` modules. Most import `legacy-bridge.css`; Vite emits it as part of the bundled CSS. The native editor also loads `app/ui/toolbar.css` followed by the large `app/ui/styles.css`. `legacy-bridge.css` imports Tailwind theme/utilities, `app/ui/panels-compact.css`, and `app/settings/panel.css`. Therefore source order and selector specificity must be preserved and verified from the emitted CSS/rendered page before consolidation.
- `app/settings.beui.js` is the currently loaded settings API implementation. `app/settings.js` contains the same style of persisted API **and** a native dialog, but is not loaded by the production entry. `app/settings/panel-adapter.js` instead mounts the native settings panel markup and adapts the `kefeSettings` API; it also expects existing section panels and some `beui-*` wrapper classes.
- `beui-*` names are not ownership evidence: native files (`desktop-panels.js`, `editor.js`, settings adapters) create/use these classes, and native CSS styles them. Do not remove or rename them based on the prefix alone.

## Selected component and current CSS ownership trace

**Selected for the first translation: the volume popover Card wrapper** (`legacy-volume-card-bridge.jsx`). It is a clear decorative boundary: audio and open/close logic already live in KEFE; only a React Card is added around existing label/range/output DOM. The native range bridge remains independently needed and is not part of this removal.

Confirmed cascade in the emitted `dist-beui/assets/style-*.css` at this snapshot:

- `.kefe-volume-popover` base placement/width/border/surface/shadow and label/range/output rules originate in `app/ui/styles.css` around lines 6777–6785; the mobile rule is around line 6787. The native popover sets `display:flex`, horizontal alignment and a 10px gap.
- The later native styles around lines 10409–10411 set `.beui-volume-card-root { display: contents }`, reset `.kefe-volume-popover.beui-volume-popover-native` to transparent/zero padding, and make `.beui-volume-card` a flex column.
- `legacy-volume-card-bridge.jsx` adds a Card with `w-full gap-2 rounded-xl border p-3 text-foreground shadow-xl` and inline shell background/border/text/shadow. Tailwind utility rules occur later in the emitted asset; the Card’s inline styles override relevant background, border colour, text colour and shadow. The resulting visible Card is therefore the inner React Card, not the outer popover shell.
- `legacy-bridge.css` itself contains no volume-specific rules. `legacy-panel-buttons-bridge.jsx` lists `.beui-volume-card-root` as an ancestor exclusion, but the volume popover is in the timeline outside `.kefe-panel`; it is not scanned by that bridge. After removing the volume wrapper, that exclusion can be deleted only with a regression check that no panel buttons mount differently.
- Native `.kefe-volume-popover[hidden] { display:none!important }` remains critical to the native open/close controller. Its `!important` is intentional hidden-state protection, not a cleanup target.

Native translation should make the existing `.kefe-volume-popover` itself render the same flex-column Card surface, consolidate the corresponding rules into its existing native CSS block, retain its positioning/mobile width/hidden behavior, and leave the original label/input/output children untouched. The regression test must check computed card styling, four theme/viewport screenshots, volume slider visibility, Escape dismissal, and no React Card/root markers. Do not proceed with this styling edit until the current implementation has passed the supported browser suite and its baseline screenshots are available.

## CSS and runtime risk notes

- The emitted build uses one CSS asset. In `editor.source.html`, native `toolbar.css` is linked before native `styles.css`; bridge modules import `legacy-bridge.css`, which in turn imports Tailwind theme/utilities, compact-panel overrides and settings-panel CSS. Vite extracts these into the built stylesheet, so inspect the actual emitted rule order/layers and selector specificity before any cascade edit rather than relying on source order alone.
- Native files already implement substantial pieces of the beUI visual design (upload, range, tabs, panel headers, compact panels, theme overrides). Some selectors style `beui-*` hosts because these names also mark live native integration points.
- `desktop-panels.js` owns native accordion interactions and adds beUI-named classes. `settings/panel-adapter.js` moves the existing six native panels into a native settings panel and currently selects/clears beUI-named markers. These are runtime ownership facts, not candidates for deletion by prefix.
- CSS has meaningful day/night and responsive overrides plus `!important` declarations. No broad cleanup or specificity/order change is justified by this inventory alone.

## Recommended translation order (not authorization to mass-remove)

1. Resolve settings API/dialog/panel ownership and persistence contracts.
2. Translate low-complexity decorative wrappers (volume/upload/panel cards) to native DOM/CSS one at a time, preserving source DOM and host contracts.
3. Translate simple backed controls (text fields, textarea, checkbox, select, range) with explicit native event/value/keyboard regression coverage.
4. Translate section/sidebar/transport/panel buttons and visualiser tabs after full consumer/lifecycle mapping.
5. Translate command/settings dialogs last; verify focus, keyboard and persistence behavior.
6. Only then reconsider React/Tailwind/Vite workflows/dependencies and copied component sources. Keep the production entry and deploy path tested throughout; no infrastructure removal is approved by this inventory.
