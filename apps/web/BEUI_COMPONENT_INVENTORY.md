## Architecture observed

- `index.html` redirects to `apps/web/editor.html`, which serves the built `dist-beui/editor.html`. The Vite build takes `editor.source.html`, bundles the imported React/Tailwind bridges into one JavaScript bundle and one stylesheet, then `scripts/copy-static.mjs` copies the native runtime/assets.
- The editor remains predominantly KEFE-authored markup and imperative JavaScript. `app/ui/structure.js` and `app/editor.js` generate the shell/panels; runtime files consume the existing DOM and event contracts. React components mount over, wrap, or mirror those DOM elements rather than owning the whole application.
- At the original audit snapshot, `editor.source.html` loaded 15 `legacy-*-bridge.jsx` modules. The current branch entry loads 4 after the merged Card migrations, four previously removed controls, and this worktree's five-control/shell batch. Most remaining bridges import `legacy-bridge.css`; Vite emits it as part of the bundled CSS. The native editor also loads `app/ui/toolbar.css` followed by the large `app/ui/styles.css`. `legacy-bridge.css` imports Tailwind theme/utilities, `app/ui/panels-compact.css`, and `app/settings/panel.css`. Therefore source order and selector specificity must be preserved and verified from emitted CSS/rendered pages before consolidation.
- `app/settings.beui.js` is the currently loaded settings API implementation. `app/settings.js` contains the same style of persisted API **and** a native dialog, but is not loaded by the production entry. `app/settings/panel-adapter.js` instead mounts the native settings panel markup and adapts the `kefeSettings` API; it also expects existing section panels and some `beui-*` wrapper classes.
- `beui-*` names are not ownership evidence: native files (`desktop-panels.js`, `editor.js`, settings adapters) create/use these classes, and native CSS styles them. Do not remove or rename them based on the prefix alone.

## Selected component and current CSS ownership trace

**Selected for the first translation: the volume popover Card wrapper** (`legacy-volume-card-bridge.jsx`). It is a clear decorative boundary: audio and open/close logic already live in KEFE; only a React Card is added around existing label/range/output DOM. The native range bridge remains independently needed and is not part of this removal.

Confirmed cascade in the emitted `dist-beui/assets/style-*.css` at this snapshot:

- `.kefe-volume-popover` base placement/width/border/surface/shadow and label/range/output rules originate in `app/ui/styles.css` around lines 6777–6785; the mobile rule is around line 6787. The native popover sets `display:flex`, horizontal alignment and a 10px gap.
- The later native styles around lines 10409–10411 set `.beui-volume-card-root { display: contents }`, reset `.kefe-volume-popover.beui-volume-popover-native` to transparent/zero padding, and make `.beui-volume-card` a flex column.
- `legacy-volume-card-bridge.jsx` adds a Card with `w-full gap-2 rounded-xl border p-3 text-foreground shadow-xl` and inline shell background/border/text/shadow. Tailwind utility rules occur later in the emitted asset; the Card’s inline styles override relevant background, border colour, text colour and shadow. The resulting visible Card is therefore the inner React Card, not the outer popover shell.
- `legacy-bridge.css` itself contains no volume-specific rules. At the audit baseline, `legacy-panel-buttons-bridge.jsx` listed `.beui-volume-card-root` as an ancestor exclusion even though the volume popover is in the timeline outside `.kefe-panel` and is not scanned by that bridge. This PR removes the stale exclusion after confirming the DOM boundary; the full browser suite still checks panel-button host stability.
- Native `.kefe-volume-popover[hidden] { display:none!important }` remains critical to the native open/close controller. Its `!important` is intentional hidden-state protection, not a cleanup target.

Native translation makes the existing `.kefe-volume-popover` itself render the same flex-column Card surface, consolidates the corresponding rules into its existing native CSS block, retains its positioning/mobile width/hidden behavior, and leaves the original label/input/output children untouched. The surface uses the same `--shell-panel`, `--shell-text`, and `--shell-line` tokens as the React Card and preserves the original transparent/current-color fallback when those tokens are absent in night mode. Do not substitute generic KEFE panel fills here: the baseline's mobile/night crop demonstrates that the surrounding timeline remains visible through the Card. The regression test checks computed Card styling, four theme/viewport screenshots, volume slider keyboard/state behavior, Escape dismissal, and absence of React Card/root markers. The supported-browser baseline passed in CI run `40480900686` and its artifact downloaded successfully inside CI. The first post-translation browser run exposed a real regression assertion: the Card outline computed to `0px` because the new rule referenced an unavailable night-theme token. A subsequent browser run passed the interactions and styling assertions, but the pixel comparison exceeded its 2.5% budget. The screenshot artifact was uploaded, but could not be retrieved from this sandbox because GitHub’s artifact blob host is blocked; CI now exposes comparison diagnostics in check annotations. A geometry probe showed the wrapper's `gap-2` and `p-3` resolve to 7px and 10.5px at KEFE’s 14px root size; the earlier native values of 8px/12px made the Card 5px taller. The current working-tree correction uses those computed values, preserves the Card’s default cross-axis alignment, and restores the original `--shell-*` theme tokens where defined. The latest browser smoke passed in CI run `40488376258`; the four-crop comparison against the pre-translation baseline reported desktop/night 0.290%, desktop/day 0%, mobile/night 0.238%, and mobile/day 0.023%, all below the 2.5% changed-pixel budget. The preceding comparison showed that the mobile/night baseline exposes the timeline behind the Card (transparent fallback), so the native CSS preserves that behavior. The browser run also verifies native structure, Card geometry, theme surfaces, viewport fit, volume keyboard/audio updates and Escape dismissal.
